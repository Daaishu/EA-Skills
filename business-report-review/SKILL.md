# Business Report Review

## Overview

对集团业务战略研讨会前的业务汇报材料进行预审，替决策者提前把关。立场为集团最高决策层（董事会/经营层）视角，而非帮汇报人改稿。报告含：总评与成熟度评级（开门见山）、内容与逻辑解构、预审重点意见、建议会上追问的问题。其中"逻辑评估""预审重点意见""追问问题"是报告重点，"核心议题""叙述方式"应精炼呈现。事实核验区分内部一致性（可下结论）与外部事实存疑（只列不下结论），不替外部事实担保。

## When to Use

触发场景：用户提交业务汇报材料、战略研讨材料、经营/述职汇报，并要求审核、点评、预审、把关、先行审阅。

材料形式：PDF、PPT（.pptx）、Word（.docx）均可。

典型触发语：
- "审核这份汇报材料"
- "点评一下这份业务汇报"
- "预审这份战略研讨材料"
- "帮我先看看这个汇报"

## Workflow

### Step 1 · 接收与解析材料

读取汇报材料全文，务必覆盖正文、图表、备注：

- PDF：用 Read 工具按页读取（提取图文）。
- PPT（.pptx）/ Word（.docx）：优先用 Read 工具读取；若不支持直接解析 Office 格式，按以下优先级兜底——
  1. 优先调用环境中可用的 Office/pptx/docx 解析 skill；
  2. 解压读取 word/document.xml 或 ppt/slides/*.xml 提取文本（注意：此路径只能拿文本，**图表、图片、表格排版会丢失，文本顺序可能错乱**）；
  3. 对图表密集的材料，将幻灯片导出为图片逐页视觉读取，避免关键数据遗漏。

识别汇报基本信息：汇报主题、汇报单位/汇报人（如材料中体现）、材料形式、篇幅与结构概览。

### Step 2 · 板块一：内容与逻辑解构

本板块分两部分："核心议题 + 叙述方式"精炼，"逻辑评估"为重点。

**A. 核心议题（精炼）**
用 1-3 句话讲清这份汇报在回答什么问题、想推动什么决策。不堆砌细节。

**B. 叙述结构与方式（精炼）**
梳理汇报的逻辑骨架，如"现状—问题—方案—资源诉求"、"目标—路径—里程碑—风险"、"成绩—挑战—举措—请求"等。点到为止。

**C. 逻辑评估（重点）**
逐项检查并明确标注结论与位置（页码/章节/幻灯片号）。**问题按严重程度分级标注：致命 / 重要 / 提示，避免大小问题混在一起稀释重点。**

- **内部一致性核查（可下结论）**：口径前后是否矛盾、数字加总是否对得上、同一指标在不同页是否打架、有无明显错别/过时信息。可下"【未发现问题】"或"【存在问题】+ 说明 + 位置"。
- **外部事实存疑项（只列、不下结论）**：市场规模、竞品数据、政策表述等需外部核实的数字——**只列出需要会前人工核实的关键项，不打"【无问题】"**。AI 只拿到材料本身，核验不了外部事实，替决策者担保外部事实为真属越界失误。
- **重点清晰度**：核心结论是否突出、是否被冗余信息淹没、关键信息是否缺失。
- **逻辑缺失**：论证链条是否完整、有无逻辑跳跃/偷换概念/以偏概全/因果错配。
- **数据支撑度**：关键结论是否有数据/事实支撑、数据来源是否可信、引用口径是否合理。

标注措辞：用"【未发现问题】"而非"【无问题】"——前者不越界（基于已解析材料未发现），后者等于替外部事实担保。未发现问题也要明确说明，不可笼统带过。

### Step 3 · 板块二：预审重点意见（重点）

本板块是报告灵魂。**形成顺序：先独立、后查漏——透镜做守门员不做编剧。**

**第一步 · 独立形成判断**：先不查透镜，凭材料本身与决策者直觉，形成"决策者最该说什么"的三点判断。三点应贴这份汇报，而非任何框架的展开。

**第二步 · 透镜查漏**：加载 `references/decision-maker-lens.md`，按"雷达常开 3 维 → 情境查漏 8 维"的顺序过一遍。看有没有遗漏更要命的角度——有则替换或补充，没有不强加。透镜仅作启发，不机械套用、不逐条打勾。

三点意见原则：
- **全局视野**：跳出单一业务线，看对集团整体战略/资源/时机的意义；看长期价值与风险权衡；看汇报是否回答了决策者真正关心的问题。
- **最重要**：宁少而精、不凑数；三点必须是对决策有实质影响的判断，避免细枝末节。
- **不预设结构**：表扬、批评、不足、建议皆可，视汇报内容自由组合——可以三点都指向风险，也可都指向机会，也可混合。

每点写明：
1. 意见本身（一句话核心判断）
2. 指向标签（表扬 / 批评 / 不足 / 建议）
3. 理由与依据（为什么这是最重要的）

### Step 4 · 总评与成熟度评级

基于前述分析给出开门见山的总判断，回答决策者第一反应——"这份材料到底行不行"：

- **总评**：1-3 句话概括材料质量与核心症结。
- **成熟度评级**（三选一，按逻辑评估的致命/重要问题数判定）：
  - 可直接上会：致命问题 0 个 + 重要问题 ≤2
  - 建议修改后上会：致命 ≤1 或重要较多但可补救
  - 建议重做：致命 ≥2

总评置于报告最前（决策者先看总评，再看分项）。

### Step 5 · 建议会上追问的问题

预审不止点评材料，更在武装决策者进会场。基于透镜里的追问逻辑（凭什么能达成、路线图在哪、资源够不够等），提炼 3-5 个**建议现场追问的问题**。

**质量约束**：追问问题必须指向汇报未答透的具体点，且应能逼出汇报人当场必须回应的答案——通用问题（如"风险是什么""预算多少"若汇报已答透）不算。每个问题注明追问指向（让汇报人补充什么）。

### Step 6 · 生成结构化报告

基于 `assets/report-template.md` 生成 Markdown 报告并交付用户。保持模板结构：总评置于最前，重点板块（逻辑评估、预审重点意见、追问问题）详写，精炼板块（核心议题、叙述方式）简写。

## Resources

- `references/decision-maker-lens.md` — 决策者思考透镜。在进行板块二（预审重点意见）时加载到上下文，作为全局视野的启发框架。当前为通用框架，待用户提供集团内部参考资料后补充增强。
- `assets/report-template.md` — 报告输出模板。生成报告时复制并填充，保持结构一致。

## Notes

- 总评与成熟度评级置于报告最前，开门见山回答"这份材料到底行不行"。
- 板块一的"核心议题""叙述方式"务必精炼，逻辑评估才是板块一的重点。
- 板块二是整份报告的灵魂，避免泛泛而谈与套话；每一点都要有实据。
- 事实核验严守边界：内部一致性可下结论（用"未发现问题"），外部事实只列存疑项，不替外部事实打"无问题"——这是预审场景最大的可信度风险点。
- 立场始终是决策者，不是汇报人——点评目的是帮决策者抓住要害，不是帮汇报人润色。
- 适用边界：透镜校准自特定集团决策风格（"3 年 10 亿""压强原则"等门槛带集团色彩），用于其他集团/行业时，规模门槛与战略决心标准需重新校准，不可直接套用。
- 若材料信息不足以支撑某项评估，明确标注"材料中未体现"，不臆测。
