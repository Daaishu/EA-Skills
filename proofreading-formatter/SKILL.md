# Chinese Document Proofreading & Formatter

把一段中文草稿变成可打印的定稿 Word 文件。两步：**先校对文字，再按指定格式排版。**

三种格式的样张请看 `docs/previews/` 下的图片，或者范例目录 `examples/format-{a,b,c}-*/output.docx`。

## 触发条件

- 用户提供中文草稿，希望得到可直接打印的 `.docx` 文件
- 用户提到 "校稿/校对/审稿/定稿/排版/打印版/改成公文格式/谈参/议程"
- 用户已有内容但对当前排版不满意，要求 "换一版格式"

不触发：用户只想讨论文本修改不要 Word 文件；用户要的是 PPT/PDF/Markdown 等其他格式。

## 三种格式

| 代号 | 场景 | 关键词线索 | 视觉特征 |
|------|------|-----------|---------|
| **A** | 政府公文（请示、报告、通知、函、批复） | 公文、请示、报告、发文、呈报 | 方正小标宋简体 标题 + 仿宋_GB2312 正文，严格 GB/T 9704 |
| **B** | 内部谈参、情况说明、会前快读、工作汇报 | 谈参、情况说明、汇报、会前快读、接待、背景材料 | 黑体标题 + 仿宋正文，纯黑，关键数据下划线/加粗 |
| **C** | 正式活动议程、行程安排、人员名单 | 议程、行程、名单、活动安排、座谈 | 大字居中标题 + 时间地点 + 分页人员名单 |

## 执行流程

### 第 1 步：确认格式

如果用户没明说，按关键词线索判断。判断不出就问用户：

> "这份材料希望输出成哪种格式？A. 政府公文 / B. 内部谈参汇报 / C. 活动议程"

### 第 2 步：读格式规范

**必须读** `references/format-specs.md` 中对应格式的章节。里面有字体名、字号、行距、页边距、缩进、标题层级等全部参数。

### 第 3 步：文字校对

五类检查，详见 `references/proofreading-rules.md`：

1. **错别字** —— 同音字、形近字混淆
2. **病句** —— 语法错误、搭配不当、成分残缺
3. **标点** —— 中文全角、英数半角；书名号/引号/括号成对；顿号→逗号→分号层级；省略号用 `……` 不用 `...`
4. **数字用法** —— 公文中序数词用汉字（"第一""一是"），统计数据用阿拉伯数字
5. **专名一致性** —— 人名、机构名、地名前后统一

**把所有修改项列成清单**，稍后向用户汇报。不要偷偷改动。

### 第 4 步：生成内容 JSON

把校对后的文本按 `references/content-schema.md` 的结构写成 JSON 文件。

**重要**：不要直接在 JavaScript 字符串里拼中文——中文引号、破折号、省略号会引发转义问题。始终通过 JSON 文件传递内容。直接照着 `examples/` 下的范例结构填就行。

### 第 5 步：调用构建脚本

```bash
node scripts/build_docx.js <content.json> <output.docx> <format>
```

参数：`<format>` 为 `a`、`b`、`c`（小写）。脚本输出确认信息或错误到 stderr。

**输出文件命名规则**：交付给用户的最终 `.docx` 文件，文件名一律采用「文档主标题 + 打印版」的格式，例如：

- `浙江省嘉兴市委书记座谈背景材料 打印版.docx`
- `关于申请2026年度城市绿化专项资金的请示 打印版.docx`
- `第十届国际可持续城市发展论坛议程 打印版.docx`

主标题取 content.json 里 `title` 字段的内容；如果用了 `titleLines` 多行标题，则把各行用空格拼起来。文件名中的"打印版"三个字是固定后缀，标题与"打印版"之间用一个半角空格分隔。不要用其他后缀（如 _v1、_final、_格式B 等）。

### 第 6 步：校验输出

如果环境里有 `/mnt/skills/public/docx/scripts/office/validate.py` 就调用一次做校验；没有的话，至少确认脚本退出码为 0、输出文件大小 > 5KB。

### 第 7 步：汇报

向用户报告：

1. 校对了哪些内容（每条一行，注明修改理由）
2. 用的是哪种格式
3. 提交生成的 `.docx` 文件

汇报格式示例：

```
已完成校对与排版。

【校对修改】
- 原文"做为" → "作为"（错别字）
- 原文"规化" → "规划"（错别字）
- 原文"..." → "……"（省略号规范）

【输出】格式 A（政府公文报告）
[附 output.docx]
```

## 常见问题

**字体显示不正确**：方正小标宋简体等字体只在政府公文环境和部分办公系统里可用。其他环境会自动退化到同系字体（如宋体、华文中宋）。这是正常行为，不需要干预。

## 依赖

- **Node.js 18+**，全局安装 `docx` 包：`npm install -g docx`
- 不访问网络，不读取 JSON 之外的任何文件
