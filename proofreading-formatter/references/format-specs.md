# Format Specifications

三种输出格式的完整排版参数。单位说明：

- **DXA**：1440 DXA = 1 英寸 = 2.54 cm。docx 的页边距、缩进、行距均用 DXA 表示
- **sz**：半磅值。三号字 = 16 pt = `sz: 32`；二号字 = 22 pt = `sz: 44`；小四 = 12 pt = `sz: 24`

所有三种格式共用的页面参数：

- 纸张：A4，`width: 11906, height: 16838`
- 中文字体退化链：仿宋_GB2312 → 仿宋；楷体_GB2312 → 楷体；方正小标宋简体 → 华文中宋 → 宋体

---

## Format A — 政府公文报告

严格参照 GB/T 9704 与常见央国企公文模板。

### 页面

| 参数 | 值 |
|------|---|
| 上边距 | 2098 DXA（约 37 mm） |
| 下边距 | 1985 DXA（约 35 mm） |
| 左边距 | 1588 DXA（约 28 mm） |
| 右边距 | 1474 DXA（约 26 mm） |
| 页脚距底 | 1134 DXA |

### 字体

| 层级 | 字体 | 字号 | 是否加粗 | 备注 |
|------|------|------|----------|------|
| 主标题 | 方正小标宋简体 | sz 44（二号） | 否 | 居中，段前 312、段后 312 |
| 一级标题 一、 | 黑体 | sz 32（三号） | 否 | 首行缩进 640 |
| 二级标题 （一） | 楷体_GB2312 | sz 32 | 否 | 首行缩进 640 |
| 三级标题 1． | 仿宋_GB2312 | sz 32 | 否 | 首行缩进 640，末尾加句号 |
| 四级标题 （1） | 仿宋_GB2312 | sz 32 | 否 | 首行缩进 640，末尾加句号 |
| 正文 | 仿宋_GB2312 | sz 32 | 否 | 首行缩进 640，两端对齐 |
| 正文强调 | 楷体_GB2312 | sz 32 | 否 | 不加粗、不变色 |

### 行距

- 全文统一：固定值 28 磅（`line: 560, lineRule: "exact"`）
- 标题段前段后：312 DXA

### 标题断行规则（重要）

公文标题一行放不下时，**不能让 Word 自动换行**，必须主动在语义完整处断开，拆成多个居中段落。断句原则：

1. "关于……的"作为完整介词结构留在同一行
2. 不拆散人名、机构名、职务名
3. 每行长度均衡，呈梯形或菱形分布
4. "关于"不得单独留在行首成为极短一行

**断句示例：**

| 原标题 | 错误（自然折行） | 正确（主动断行） |
|--------|-----------------|-----------------|
| 关于 XX 大学 YY 校长来访接待工作方案的报告 | 关于 XX 大学 YY 校长来访 / 接待工作方案的报告 | 关于 XX 大学 YY 校长 / 来访接待工作方案的报告 |
| 关于申请 2026 年度专项资金的请示 | 一行硬塞 | 关于申请 2026 年度 / 专项资金的请示 |

实现方式：在 content.json 中用 `titleLines` 字段手动指定每行文本。

### 层级标号规范

- 第一层：一、 二、 三、 ……
- 第二层：（一）（二）（三）……
- 第三层：1．2．3．……（全角句点"．"）
- 第四层：（1）（2）（3）……

### 落款

单位名称右对齐仿宋_GB2312 三号，日期右对齐同字体同字号。

### 页码

页脚居中，宋体小四（sz 28），格式 `— 1 —`（em-dash + 空格 + 页码 + 空格 + em-dash）。

## Format B — 内部谈参 / 情况说明 / 工作汇报

面向内部阅读，兼顾信息密度与可读性。

### 页面

| 参数 | 值 |
|------|---|
| 上边距 | 1418 DXA |
| 下边距 | 1418 DXA |
| 左边距 | 1596 DXA |
| 右边距 | 1482 DXA |

### 字体

| 层级 | 字体 | 字号 | 是否加粗 | 备注 |
|------|------|------|----------|------|
| 主标题 | 黑体 | sz 44（二号） | 是 | 居中，多行标题按梯形/菱形排列 |
| 一级标题 | 黑体 | sz 32（三号） | 是 | 左对齐不缩进，固定 28 磅行距，段前段后均为 0 |
| 二级标题 | 黑体 | sz 32 | 是 | 左对齐不缩进，固定 28 磅行距，段前段后均为 0 |
| 三级标题 | 黑体 | sz 28（小三） | 是 | 左对齐不缩进，固定 28 磅行距，段前段后均为 0 |
| 正文 | 仿宋 | sz 32 | 否 | **首行缩进 640（两字符），两端对齐，不可覆盖** |
| 标签/重点 | 仿宋 | sz 32 | 是 | 通过 {b:...} 行内标记产生 |
| 关键数据 | 仿宋 | sz 32 + 下划线 | 否 | 通过 {u:...} 行内标记产生 |

### 行距

- **正文与各级标题统一**：固定 28 磅（`line: 560, lineRule: EXACT`）
- **段前段后**：标题、正文、人物照片等各类块全部 `before: 0, after: 0`
- 标题和正文用同样的行距设置，使页面节奏整齐统一；视觉分组靠字体加粗与字号差异承担

### 主标题间距规则

主标题独享一组与众不同的段前段后：

**单行标题**：`段前 1 行（=560 DXA）、段后 1 行（=560 DXA）`

**多行标题**（长标题应主动按语义断行，要求第一行第二行长短均衡呈梯形或菱形）：

| 行 | 段前 | 段后 |
|----|------|------|
| 第一行 | 1 行（=560 DXA） | 0 |
| 中间行 | 0 | 0 |
| 最后一行 | 0 | 1 行（=560 DXA） |

这样多行标题作为整体与上下文之间有充足的呼吸空间，但内部各行之间紧密相连。

### 缩进规则

所有正文段落（`type: "p"`）必须保持首行缩进两字符。构建脚本会强制应用这条规则——内容 JSON 中没有办法取消首行缩进。这是格式 B 的设计要求，保证版面一致。

条列项（`1、` `2、` `3、`）也按正文处理，带首行缩进。不要试图用"项目符号"或"缩进不足两字符"的方式突出列表。

### 颜色规范

**纯黑色**。不使用深蓝、深红等彩色。重点信息一律通过**加粗**或**下划线**表达。

这是从实践反馈中得出的规则——彩色在打印后辨识度下降、不符合内部正式材料的风格。

### 人物照片块（用于团长简介、领导介绍等场景）

通过四个连续块组合实现"照片 + 姓名 + 职务 + 简历"的人物介绍版式：

```json
{ "type": "h1", "text": "二、团长简介" },
{ "type": "photo", "path": "examples/format-b-project-brief/sample-portrait.png" },
{ "type": "name", "text": "Dr. Michael Weber" },
{ "type": "role", "text": "慕尼黑工业大学副校长（国际合作）" },
{ "type": "p", "text": "Weber教授的简历段落..." }
```

- **照片** (`photo`)：居中独立段落，默认尺寸 200×260 像素（约 5×6.5 cm，接近证件照比例），可通过 `width` / `height` 调整
- **姓名** (`name`)：照片下方居中，黑体三号加粗
- **职务** (`role`)：姓名下方居中，仿宋三号
- **简历正文**：紧接着用普通的 `p` 段落，仿宋三号、首行缩进、固定 28 磅行距，与正文一致

### 页眉页脚

- **页眉**：居中小字"内部资料  注意保密"（仿宋 sz 18，灰色 999999），下方加浅灰装饰线（CCCCCC）
- **页脚**：居中页码 `— N —`（宋体 sz 20）

## Format C — 正式活动议程

封面级视觉，大字居中，分页清晰。

### 页面

| 参数 | 值 |
|------|---|
| 上边距 | 1800 DXA |
| 下边距 | 1418 DXA |
| 左边距 | 1596 DXA |
| 右边距 | 1482 DXA |

### 封面页

| 元素 | 字体 | 字号 | 对齐 | 行距 |
|------|------|------|------|------|
| 主标题 | 宋体加粗 | sz 44（二号） | 居中 | 800（40 磅） |
| 时间信息 | 仿宋加粗 | sz 32（三号） | 左对齐 | 800 |
| 地点信息 | 仿宋加粗 | sz 32 | 左对齐 | 800 |
| 议程条目 | 仿宋加粗 | sz 32（三号） | 左对齐 | 800 |

**格式要求：**

- 主标题分两行："XX 一行赴 XX" / "考察交流行程安排"（或类似结构）
- "时　　间：" 和 "地　　点：" 中间用**全角空格**对齐
- 议程条目格式："10:00-12:30　　A5-1 楼报告厅座谈交流"
- **所有议程条目字号统一为三号 sz 32**（无论是 `meta.agendaItem` 还是 `body[]` 中的 `p` 块），并使用相同的固定行距（800 = 40 磅）。视觉间隔靠行距本身产生，不要在议程条目之间插入 `emp` 空段——这会导致行间距不规则
- 构建脚本会忽略 `body` 中的 `emp` 块（仅对格式 C 生效）

### 名单页（独立 section）

| 元素 | 字体 | 字号 | 对齐 | 行距 |
|------|------|------|------|------|
| 页面标题"人员名单" | 仿宋加粗 | sz 44 | 居中 | 560（28 磅） |
| 单位分组标题 | 仿宋加粗 | sz 32 | 左对齐 | 560（28 磅） |
| 人员条目 | 仿宋 | sz 32 | 左对齐 | **560（28 磅）默认 / 480（24 磅）紧凑** |

**人员条目格式：**

- 两字姓名中间补**全角空格**（如"王　伟"），使其宽度与三字姓名一致
- 姓名与职务之间用**两个全角空格**分隔

**名单排序：**

- 按职务级别从高到低
- 客方（来访方）在前，主方（接待方）在后

### 名单页自动分页规则

构建脚本根据总人数和分组数自动决定名单页的分页策略：

| 总人数 | 分组数 | 行距 | 分页 |
|--------|-------|------|------|
| ≤ 14 人 | 任意 | 28 磅 | 全部放一页 |
| 15–18 人 | 任意 | 24 磅（紧凑模式） | 全部放一页 |
| > 18 人 | ≥ 2 组 | 28 磅 | **每组独占一页** |
| > 18 人 | 1 组 | 24 磅（紧凑） | 全部放一页 |

阈值（18 人）和紧凑行距（24 磅）写死在 `scripts/build_docx.js` 的 `buildFormatC` 函数中。当客方人数较多需要单独一页凸显时，把客方放在第一组、主方放在第二组即可触发"每组独占一页"。

### 页眉页脚

- 页眉：**留空**（本技能为通用模板，如需机构 Logo 请在生成后手动添加）
- 页脚：居中页码 `— N —`

## 通用规则

### 中文字体在 docx-js 中的设置

```javascript
new TextRun({
  text: "正文内容",
  font: { name: "仿宋", eastAsia: "仿宋" }, // name 与 eastAsia 都要设
  size: 32
})
```

### 行距设置

```javascript
new Paragraph({
  spacing: {
    line: 560,
    lineRule: LineRuleType.EXACT  // 必须用 EXACT 才是固定行距
  }
})
```

### 首行缩进（两字符）

```javascript
new Paragraph({
  indent: { firstLine: 640 } // 三号字两字符 ≈ 640 DXA
})
```
